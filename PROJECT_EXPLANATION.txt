1. PROJECT OVERVIEW
--------------------------------------------------------------------------------

Project name: leetcode-automation (folder: leetcode-automation)

Purpose: Solve LeetCode problems on the user's OWN account by submitting
already-banked Python 3 solutions automatically, and keep a local ledger of
what is solved so future runs only attempt unsolved problems.

Problem it solves: Manually opening, pasting and submitting hundreds of
problems is slow (~2 min/problem naively, 30-90 sec wasted per problem if you
poll the wrong verdict endpoint). This project cuts it to ~20 sec/problem
(often 2-5 sec for the verdict) and allows 4 banks in parallel for ~4x
throughput. It avoids repeat work by caching questionIds, CSRF tokens and the
solved list locally.

Main technologies:
- Python 3 stdlib only (json, subprocess, time, sys, os, re, urllib, glob).
  No pip dependencies for the solver.
- Windows curl.exe as the HTTP client. All LeetCode traffic goes through
  curl subprocess calls.
- LeetCode HTTP APIs: GET / (CSRF refresh), GET /api/problems/all/ (catalog),
  GET /graphql/?query=... (questionId + recentAcSubmissionList verdicts),
  POST /problems/<slug>/submit/ (submit python3 code),
  GET /submissions/detail/<id>/check/ (definitive check).
- Node.js v16+ + Playwright ^1.62.1 + Chromium for browser variant and cookie
  extraction (see package.json).
- Windows Batch (.bat) self-restarting runner loops.
- JSON solution banks: { "problem-slug": "python3 code", ... }.
- Plain-text ledgers (solved.txt, unsolved.txt) as skip lists.

Final result / output:
- Real Accepted submissions on the user's profile (670 solved as of
  2026-09-15 per START-HERE.md, target was 643).
- Local evidence: runner*.log / run*.log lines like "[12] slug: Accepted"
  plus "END solved: <N> accepted this run: <M>".
- Refreshed ledgers: solved.txt (670 slugs), unsolved.txt (433 unsolved
  easy), unsolved_medium.txt (2004 unsolved medium per START-HERE.md).
- Reusable archive: SOLUTIONS_MASTER.json (454 unique, verified),
  SOLUTIONS.md (human-readable), SOLUTIONS_INDEX.md (bank inventory).

2. HOW THE PROJECT WORKS
--------------------------------------------------------------------------------

Two paths exist. Primary/fast path is the API path (solver2.py).
Secondary/slow path is the browser path (leetcode_automation.js).
PRIMARY PATH - API SUBMITTER (solver2.py), chronological order:
INPUT: bank JSON (solutions_y1.json, solutions_gen1.json, solutions_all.json;
slug -> python3 class Solution code); lc_cookies.txt Netscape jar
(LEETCODE_SESSION + csrftoken via node get_cookie.js or manual copy, see
lc_cookies.txt.example); solved.txt skip ledger (header e.g.
"solved: 670 | updated: 2026-09-15 22:48" + one slug per line); qids.json
cache (slug -> questionId). Command: python solver2.py <slug|x> <bank> <cap>,
e.g. python solver2.py x solutions_y1.json 32. "x" = whole bank. Defaults:
bank solutions_all.json, cap 50 (stop after N Accepted).

INITIALIZATION (read_session, curl, refresh_csrf): read last TAB field of
LEETCODE_SESSION line; curl GET https://leetcode.com/ with -b lc_cookies.txt
-c lc_cookies2.txt then append session line (binds jar); parse csrftoken,
print "csrf: True/False"; load qids.json to QIDS and solved.txt to SOLVED
(ignore blanks + headers LEETCODE/Generated/Total/=, the golden skip rule);
GET /api/problems/all/ to build status map from stat_status_pairs; print
"START solved: <num_solved> | ledger size: N".

PROCESSING (file-order loop): skip if argv filter mismatches or accept >= cap
("reached cap" break). If slug in SOLVED or status=="ac" print
"[N] slug: already solved skip" with zero HTTP. Else submit(): get_qid via
cache or GraphQL query{question(titleSlug){questionId}} with write-through to
qids.json (missing = premium/locked = SKIPPED); POST
/problems/<slug>/submit/ {"lang":"python3",...} + X-CSRFToken/Referer/jar,
retry 4x (sleep 3/6/9s) if submission_id missing else None. Print
"[N] slug: <verdict>", count Accepted, sleep 1.5s cooldown.

ANALYSIS (get_verdict_recent, two-phase trick): Phase 1 fast (~2-5s): 5x
sleep 1.5s + GET recentAcSubmissionList(username "lavcha", limit 15), return
on slug match (usually Accepted). NOTE "lavcha" hardcoded, MUST edit to your
username or all degrade to TIMEOUT. Phase 2 definitive: 14x sleep 2s + GET
/submissions/detail/<id>/check/; map 10 Accepted, 11 Wrong Answer, 12 Memory
Limit, 13 Output Limit, 14 Time Limit, 15 Runtime Error, 20 Compile Error,
else status_msg/UNKNOWN; else TIMEOUT. Rationale: /check/ via curl stays
PENDING 30-90s; 1KB GraphQL list resolves Accepts fast, /check/ catches rest.
DECISIONS: SKIPPED / None / Accepted / Wrong/Runtime/etc / TIMEOUT / skip.
OUTPUT: runnerN.log lines + re-GET catalog "END solved: N accepted M".
Side effects lc_cookies2.txt + grown qids.json.
VALIDATION: check_login.py before (num_solved>0), regen_ledgers.py after,
prep_banks.py + build_archive.py (sections 9-10).

SECONDARY PATH - BROWSER (leetcode_automation.js): INPUT 5 hardcoded JS
problems (Stock IV, Two Sum, Valid Parentheses, Climbing Stairs, Merge Two
Sorted Lists). INIT chromium headless:false slowMo:50, 1920x1080, Chrome/120
UA, goto /accounts/login/, manual login + ENTER. PROCESSING solveProblem():
goto url (networkidle), 2s, CAPTCHA check, fill Monaco (click/Ctrl+A/Delete/
type 20ms) or textarea, 2s, try 4 submit selectors, click, 15s. ANALYSIS
scrape result DOM (200 chars) or Accepted/Wrong markers. OUTPUT terminal
"COMPLETE: n/m". VALIDATION human watches, ENTER-resume CAPTCHA pauses, 2s
delays. Reference only, not bulk solving.

ANALYSIS: phase-1 match -> statusDisplay; phase-2 code -> 10..20 text; else
TIMEOUT/None/SKIPPED. FINAL: remote submission + ac + num_solved bump; local
runner/run logs verdicts; ledgers via regen_ledgers.py; archive via
build_archive.py. STORAGE: filesystem only, no DB; JSON + TAB jars + slug
lists + bat + md. No AI APIs. BROWSER PATH: JS strings -> Monaco DOM ->
Submit click -> judge -> DOM scrape -> terminal, no files.

10. HOW TO RUN (verified only, from docs/source)
--------------------------------------------------------------------------------
Prereqs (browser): npm install | npx playwright install chromium
1) Cookie: node get_cookie.js (Chromium login, auto-writes jar, 900s). Manual:
same-machine F12 -> Cookies -> leetcode.com, copy LEETCODE_SESSION
([SECRET OMITTED] ~800 chars, NOT eyJ JWT) + csrftoken ([SECRET OMITTED])
to lc_cookies.txt TAB format (see example).
2) Verify: python check_login.py (need LOGIN OK, num_solved>0).
3) Validate: python prep_banks.py (non-ascii 0, no BAD).
4) Foreground: python solver2.py x solutions_y1.json 32 (syntax <slug|x>
<bank> <cap>; e.g. x solutions_gen1.json 50).
5) Parallel 4x: edit runner10..13.bat (or copy runner_tmpl.bat %~dp0), launch
detached: Invoke-CimMethod -ClassName Win32_Process -MethodName Create
-Arguments @{CommandLine='cmd /c C:\path\to\folder\runner10.bat'} (repeat
11-13). Monitor: Get-Content runner10.log -Tail 3 |
(Get-Content runner10.log | Select-String 'Accepted').Count. Stop:
Get-Process python -ErrorAction SilentlyContinue | Stop-Process -Force
6) Ledgers: python regen_ledgers.py (rewrites sets). Offline: regex Accepted
from runner10-13.log, MERGE into solved.txt (never overwrite; START-HERE 6).
7) Archive: python build_archive.py (master/md/index).
8) Debug: python solver2.py <slug> <bank> 1 | python t_submit.py |
python t_check.py <sid> | python t_prob.py <slug>
9) Demo: node leetcode_automation.js (manual login/ENTER/CAPTCHAs/ENTER).
Per-person edit: solver2.py username "lavcha" -> yours, else TIMEOUT.
